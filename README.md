# AKS + Azure Database for PostgreSQL Terraform project

This is a production-oriented learning/reference baseline, not a turnkey production deployment. Review all network ranges, Azure quotas, provider compatibility, private DNS behavior, access policies, and cost before applying.

## Included
- Azure Resource Group and Log Analytics workspace
- AKS cluster(s) using `for_each`
- Separate VNet, AKS node subnet, and delegated PostgreSQL subnet per map entry
- AKS system and user node pools
- Azure CNI Overlay, Azure Network Policy, Standard Load Balancer
- Azure RBAC enabled and local Kubernetes accounts disabled
- Azure Monitor Container Insights integration via Log Analytics
- Azure Database for PostgreSQL Flexible Server (private access via delegated subnet/private DNS)
- PostgreSQL `appdb` database
- Kubernetes namespace, NGINX Deployment, LoadBalancer Service
- Secret manifest template (not real credentials)

## Important architecture note
The included NGINX container is only a web-server workload; it does not itself connect to PostgreSQL. The Terraform code provisions the database infrastructure, but a database-aware application (with a PostgreSQL driver and connection configuration) is still required to prove application-to-database connectivity. The Secret example is only a template. Do not put real passwords in source control.

## Before applying
1. Copy `terraform.tfvars.example` to `terraform.tfvars`.
2. Set your real Azure subscription ID.
3. Set a globally unique PostgreSQL server name (lowercase letters, digits, hyphens; validate Azure naming requirements).
4. Kubernetes version `1.36.4` came from the user's `az aks get-versions --location eastus` output; verify it remains supported in the chosen region/subscription before apply.
5. Confirm the VM SKUs and quotas are available in East US.
6. Ensure VNet, AKS subnet, PostgreSQL subnet, and service CIDRs do not overlap with connected networks. The VNet must be large enough for AKS and the delegated PostgreSQL subnet.
7. Configure remote Azure Storage backend with encryption, locking, and restricted access before production use. `backend.tf.example` is a template; edit and rename to `backend.tf` only after creating the storage account/container.
8. Review private DNS, egress, private AKS API endpoint, Entra ID/RBAC, alerting, backups, high availability, and Key Vault/Workload Identity design.
9. PostgreSQL passwords are generated by Terraform and stored in Terraform state. Protect state access; do not output or commit passwords. For a real production system, integrate a proper secret-management flow.
10. Validate resource arguments against the selected AzureRM provider and current Azure service constraints.

## Provision infrastructure
Run from this folder in PowerShell:

```powershell
Copy-Item terraform.tfvars.example terraform.tfvars
# Edit terraform.tfvars first
terraform fmt -recursive
terraform init
terraform validate
terraform plan
terraform apply
```

Use the actual Resource Group name in commands (default: `mahesh-aks-prod-rg`).

## Connect to AKS and deploy Kubernetes manifests

```powershell
az login
az aks get-credentials --resource-group mahesh-aks-prod-rg --name mahesh-aks-prod --overwrite-existing
kubectl get nodes
kubectl apply -f .\k8s
amespace.yaml
kubectl apply -f .\k8s\deployment.yaml
kubectl apply -f .\k8s\service.yaml
kubectl get pods -n production
kubectl get svc -n production
```

The LoadBalancer Service exposes NGINX publicly; use only when that is intended. Production ingress should have deliberate TLS and access restrictions.

## PostgreSQL outputs and connectivity

```powershell
terraform output postgres_server_fqdns
terraform output postgres_database_names
```

Private DNS/networking must resolve and route from the AKS VNet. Test from an approved client/network. The included NGINX image has no PostgreSQL client/application integration; add a database-aware app before claiming end-to-end DB connectivity.

## Destroy only a disposable test environment

```powershell
terraform plan -destroy
# Review carefully, then only if you intend to delete all managed resources:
terraform destroy
```
